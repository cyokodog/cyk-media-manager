# Issue #14 作業ログ

https://github.com/cyokodog/cyk-media-manager/issues/14

## 2026-09-08 サムネイルのファイル名をダブルクリックで個別にリネーム

### やったこと

左右列のファイル名をダブルクリックすると、その場で `<input>` に差し替わり
名前を編集できるようにした。Enter / blur で確定、Esc で取消。

サーバーに `POST /api/rename/one` を追加。`checkSingleRename()` で検証し、
実行は既存の `applyRenamePlan()` を1件で呼ぶ（ロールバックを流用できる）。

### 見つけたバグ: 1回目のクリックで DOM が差し替わり dblclick が成立しない

**これが本題より重要。** `handleThumbClick` が最後に `renderColumn()` を
呼んでおり、1回目のクリックでサムネイルの DOM が丸ごと作り直されていた。
2回目のクリックは別の要素に当たるため、ブラウザが `dblclick` を発火しない。

イベントログで確認した:

```
["click:1:name","click:2:name"]        ← dblclick が無い
```

選択状態はクラスの付け替えだけで足りるので、`syncSelectionClasses()` を
足して**要素を作り直さない**ようにした。中央列（`handleCenterClick`）も
同じ問題があったため同様に修正。

```
["click:1:name","click:2:name","DBLCLICK:name"]   ← 修正後
```

これは E2E だけの問題ではなく、実ブラウザでも同じ挙動になる。

### 決めたこと

- **編集できるのは左右列のみ。** 中央列は連番リネームの対象なので、そこで
  個別に名前を変えられると挙動が分かりにくくなる
- **拡張子は編集対象に含めない。** 編集中は名前部分だけを表示し、確定時に
  元の拡張子を付け直す。誤って拡張子を消す事故を防ぐ
- **中央列に投入済み（追加済み）は編集不可。** ドラッグも選択もできない状態と
  揃えた
- パス区切り（`/` `\`）と `.` `..` はサーバー側で弾く。ディレクトリ外への
  書き込みを防ぐため
- 大文字小文字だけの変更（`photo.png` → `Photo.png`）は許可する。
  ケース非依存のファイルシステムでも `applyRenamePlan` の2段階リネームが
  `.__tmp__` を経由するため成立する

### 検証

`npm test` で66テスト（既存54 + 新規12）すべて通過。

新規12件は、編集の開始・拡張子の除外・全選択、Enter / Esc / blur、変更なし・
空文字、既存ファイルとの衝突、パス区切りの拒否、並び順の更新、追加済みの
編集不可、左列での編集、大文字小文字だけの変更。

リネームは破壊的なので、テストは `os.tmpdir()` の使い捨てディレクトリで
実行している。

### ハマった点

**1. Playwright の `locator.dblclick()` が使えない。** `draggable` な要素の
上では 2連クリックが drag 判定に吸われ、`dblclick` が発火しない。
`page.mouse.click(x, y, { clickCount: 2 })` で座標を直接指定して回避した。
ヘルパー `startEdit()` にまとめてある。

**2. 古いサーバーが使い回されて 404 になった。** `playwright.config.js` の
`reuseExistingServer` により、エンドポイントを追加する前に起動したプロセスが
生き残っていた。`/api/rename/one` が 404 を返して原因を見失いかけた。
**サーバー側を変更したら `lsof -ti:3456 | xargs kill` してからテストする。**

### 検証していない点

- 実ブラウザでの手動操作。ヘッドレス Chromium のみ
- IME での日本語入力中の Enter（変換確定と確定操作が競合しうる）
