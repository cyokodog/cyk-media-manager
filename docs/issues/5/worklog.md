## 2026-09-06 中央列のD&D並べ替えと複数選択・クリア機能

### やったこと

中央列を本実装した。#4 で作った `state.targetOrder` を情報源に、
並べ替え・選択・削除・連番表示を載せている。

- 中央列内の D&D 並べ替え（複数まとめても可）
- 挿入位置の縦ライン表示
- cmd/ctrl トグル選択、shift 範囲選択
- 連番バッジ（既定 4桁 / 開始10 / ステップ10 → `0010, 0020...`）
- ヘッダーの「全クリア」ボタン
- サムネイルごとの × ボタン（ホバー時に表示）

### 決めたこと

- **SortableJS の読み込みを削除した。** #4 の時点で MultiDrag が使えないことが
  判明しており（`Sortable.MultiDrag is not a constructor`）、複数まとめての
  並べ替えはどのみち自前実装が必要だった。左右列と同じネイティブ D&D に
  方式を統一した方が保守しやすいため、依存ごと外した
- **中央列のドラッグには move と remove の両方の MIME を載せている。**
  中央列内に落とせば並べ替え、左右列に落とせば削除、という振り分けのため。
  中央列内で誤って削除されないことをテストで担保している
- **挿入位置**は、カーソルに最も近いサムネイルの左端／右端から求める
  （`insertIndexAt()`）。グリッドで折り返すため、単純な x 座標比較では
  行をまたいだときに破綻する
- **複数まとめての移動**では、挿入位置より前にある移動対象の数だけ index を
  詰める（`reorderTarget()`）。詰めないと移動元が抜けた分だけずれる
- 連番の既定値は `seq` オブジェクトに置いた。**#6 でフッターの入力と連動させる**

### 検証

`npm test` で33テスト（既存21 + 新規12）すべて通過。完了条件9項目すべてに対応がある。

SortableJS を外したので既存テストへの影響を確認したが、全て通っている。
`typeof window.Sortable === 'undefined'` を確かめるテストも足した。

スクリーンショットで連番バッジ・×ボタン・全クリア・選択状態を目視確認した。

### E2E の注意

`drag()` ヘルパーに `clientX` / `clientY` を渡せるようにした。並べ替えは
ドロップ座標で挿入位置が決まるため、座標を指定しないと検証にならない。
`dropBefore()` は対象サムネイルの左端 +2px を狙う。

**× ボタンはホバー時のみ表示される**ので、テストでは `hover()` してから
クリックする必要がある（最初これで失敗した）。

### 検証していない点

- **実ブラウザでの手動 D&D**。#4 と同じく Playwright ではネイティブ D&D を
  駆動できないため合成イベントで代替している。ドラッグ画像やカーソル形状、
  スクロール中の挙動は未確認
- ヘッドレス Chromium のみ。Safari / Firefox は未確認
- 大量ファイル（数百件）での並べ替えの操作感

### #6 への申し送り

- `seq` オブジェクト（`digits` / `start` / `step`）をフッターの入力と連動させ、
  変更時に `renderCenter()` を呼べば連番バッジが更新される
- `state.targetOrder` がリネーム対象と順序。`state.dir` が対象ディレクトリ
- フッターは #3 で見た目だけ作ってあり、確定ボタンは常に無効のまま
